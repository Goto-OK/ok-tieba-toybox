# 需求与边界

## 1. 背景

贴吧帖子页的楼层和楼中楼没有方便的批量导出工具。本项目面向需要统计“谁回复了多少、
发了什么”的个人用户，提供 Windows 桌面程序和命令行。

## 2. 目标用户

- 想导出某个帖子参与情况的普通用户；
- 需要查看参与者资料（关注吧、最近发言）的用户；
- 未来希望在手机上临时抓公开帖子的人（Android 暂停，不在当前范围）。

## 3. 功能需求

### 3.1 抓取

- 支持一个或多个帖子链接/帖子 ID；
- 多个帖子按 tid 去重；重复链接只抓一次；
- 再次抓取时，已存在的帖子默认跳过，只抓新增帖子；
- 用户可对单个帖子显式点“重新抓取”，或清空后重抓；
- 跳过/新增/重抓都要在日志中说明；
- 「设置 → 高级 → 再次抓取时自动刷新已抓帖子」：
  - 默认关闭；
  - 关闭：已抓帖子跳过，只抓新增帖子；
  - 开启：已抓帖子也重新抓取，新帖子照常追加；
- 自动刷新只影响本次开始，不改变“删掉的旧帖子”处理规则；
- 自动刷新顺序：
  1. 先处理输入框里被移除的帖子（保留/移除/询问）；
  2. 再抓新增帖子；
  3. 最后刷新保留的旧帖子；
- 刷新成功：用新快照替换该帖旧结果；
- 替换是“当前结果替换”，不合并旧楼层、不保留旧快照；
- 旧帖里后来被删除的楼层，刷新后不再出现在当前统计；
- 刷新失败：保留旧结果，记录警告，不把该帖清空；
- 单帖「重新抓取」与自动刷新使用同一套替换逻辑；
- 自动刷新会明显变慢，界面必须提示；
- 输入框里删掉的已抓帖子，默认**保留在结果里**，不因为少粘贴一行就丢数据；
- 「设置 → 高级 → 再次抓取时处理已移除帖子」提供三个选项：
  - 保留旧结果（默认）；
  - 移除旧结果；
  - 每次询问；
- 该选项只在点「开始统计」时生效，不即时删除；
- 选“询问”时，弹窗列出被移除的帖子，让用户选择保留或移除；
- 「清空结果」始终删除全部结果，不受该选项影响；
- 自动识别总页数，逐页抓取主题楼层；
- 抓取楼中楼：默认用客户端 protobuf 逐层翻页；floor 失败且有关注增强 Cookie 时，回退网页 `totalComment` + `/p/comment`；
- 支持“最多页数”“是否抓楼中楼”“是否导出”等选项；
- 请求间隔、楼中楼深度、并发保留在抓取页，作为本次抓取参数；
- 设置页只放跨次策略（自动刷新旧帖、移除旧帖处理）；
- 支持中途停止；
- 抓取/批量运行中关闭窗口：
  - 弹窗确认“任务仍在进行，停止并退出？”；
  - 确认后停止任务，保存已完成部分（若开启保存结果），再退出；
  - 取消则继续；
  - 保存失败时提示，允许用户选择是否仍退出；
  - 不强制杀进程，避免结果文件损坏。

### 3.2 统计与导出

- 按用户汇总：楼层数、楼中楼数、合计、等级、头衔、首次出现楼层；
- 表格查看顶部提供“帖子切换”：
  - 每个已抓帖子；
  - `全部帖子（汇总）`（非默认）；
- 默认显示第一个帖子，切换后表头和明细同步切换；
- `全部帖子（汇总）`：
  - 回复统计：按用户跨帖合计，增加“参与帖子数”，不按帖子展开列；
  - 增加独立“分帖统计”子表/工作表（仅全部帖子汇总时显示）：
    - 一行 = 用户 × 帖子；
    - 列：昵称、用户名、用户ID、帖子、楼层、楼中楼、合计；
    - 只统计当前用户范围；
  - 楼层明细：增加“帖子”列，按帖子分组；
  - 楼中楼明细：增加“帖子”列，按帖子分组；
- 导出 Excel 和打开 Excel 都必须先选择范围：
  - 帖子范围：
    - 当前表格范围（默认；当前单帖或全部汇总）；
    - 全部帖子；
    - 勾选帖子（列出所有已抓帖子，可全选/反选）；
  - 用户范围：
    - 当前筛选用户（有筛选时默认；仅当参与者筛选生效时显示）；
    - 全部用户（无筛选时默认）；
  - 有筛选时，对话框显示筛选摘要和人数，例如：
    “关键词「原神」；等级 Lv.4-6；标记=红；共 12 人”；
- “当前筛选用户”指：参与者当前范围 + 当前关键词/等级/标记筛选后可见的用户；
- 选择“当前筛选用户”时，所有工作表只保留这些用户的记录，合计重新计算；
- 选择“当前筛选用户”时：
  - 某个帖子没有这些用户：跳过该帖的工作表；
  - 但“总览/帖子信息”仍保留该帖，计数标 0；
  - 所有选中帖子都为空：提示并不生成文件；
- 选择“当前筛选用户”但用户集合为空时，提示并不生成文件；
- 没有筛选时，不显示/禁用“当前筛选用户”，默认全部用户；
- 导出 Excel：保存到用户选择路径；
- 打开 Excel：用同一选择生成临时工作簿并直接打开，不要求先保存；
- 临时工作簿放系统临时目录的 `TiebaReplyStats` 子目录，不写项目目录；
- 临时文件命名带 `open_` 前缀；
- 每次启动时清理该子目录下旧的 `open_*.xlsx`：
  - 只删本软件生成的文件；
  - 被 Excel 占用的文件跳过，不报错；
  - 清理失败不影响启动；
- 未选择任何帖子时提示，不生成空文件；
- Excel 工作表固定顺序：
  - 回复统计；
  - 分帖统计（仅全部帖子汇总时）；
  - 楼层明细；
  - 楼中楼明细；
  - 帖子信息；
  - 导出说明（固定最后）；
- Excel 增加「导出说明」工作表，固定放在最后一个，记录：
  - 生成时间；
  - 软件版本；
  - 帖子范围（全部/当前/勾选，含 tid/标题）；
  - 用户范围（全部/筛选）；
  - 筛选条件（关键词/等级/标记）；
  - 筛选后人数；
  - 实际导出用户数；
  - 关注增强状态、是否勾选“包含关注”；
  - 因筛选被跳过、计数为 0 的帖子；
- 「导出说明」不包含 Cookie/BDUSS/STOKEN；
- 打开 Excel 的临时工作簿也包含该说明；
- 每帖保留完整性警告：
  - 声明楼中楼数 > 实际数；
  - 楼层号缺口；
  - 某层楼中楼失败；
  - 分页/中途停止导致不完整；
- 表格查看显示警告条：
  - 单帖：显示该帖警告；
  - 全部汇总：显示有警告的帖子数，可展开列表；
- 导出说明记录每个帖子的警告；
- 有警告不阻止导出，但必须提示；
- 超大导出拆分：
  - 单个工作表数据行超过 500,000 行时自动拆分；
  - 主文件保留第一段；
  - 超出部分生成独立文件：
    `原文件名_工作表名_part2.xlsx`、`part3`…；
  - 每个拆分文件只含该工作表 + 导出说明；
  - 不重复放统计表；
  - 导出说明记录：原文件、工作表、part 序号、行数范围；
  - 导出完成弹窗列出所有文件；
  - 打开 Excel 时，如果拆成多个文件，弹窗选择：
    - 打开全部 N 个（默认？否，见下）；
    - 只打开第一个；
    - 取消；
  - 默认按钮为“只打开第一个”；
  - 只有一个文件时不弹窗；
  - 打开失败要列出失败文件，不静默遗漏；
- 包含超链接、冻结首行、筛选、合计行。

### 3.3 参与者

- 列表展示参与者；
- 顶部提供“帖子范围”下拉：
  - “全部帖子”（默认）；
  - 每个已抓帖子；
- 默认“全部帖子”，显示跨帖合计；
- 切换单帖后只统计该帖参与者；
- 切换只影响参与者页，不改变“表格查看”的当前帖子；
- 切换帖子范围时：
  - 保留当前筛选条件；
  - 清空当前选中行；
  - 筛选后没有结果时显示“当前范围没有匹配用户”；
  - 不自动重置等级/关键词/标记；
- 下拉项要显示帖子标题/吧名，避免只显示 tid；
- 新增帖子后默认仍回到“全部帖子”。
- 点选后显示：关注贴吧（含等级）、最近发言（日期/类型/贴吧/标题/内容）；
- 支持“最近发言抓取条数”（5~1000）与日期范围；
- 支持一键批量刷新红绿灯（按用户设置条数与日期）；
- 当前帖子范围存在完整性警告时，参与者页顶部显示：
  “基础数据不完整，红绿灯结果可能漏”；
- 警告不阻止一键红绿灯；
- 关注增强也不能补齐缺失的楼层/楼中楼；
- 红绿灯默认开启；可在「设置 → 通用」关闭，关闭后不显示红绿灯列并禁用批量按钮。

#### 参与者筛选（FR-009）

在参与者列表上方增加一行筛选条：

- **关键词**：匹配昵称、用户名、用户 ID；
  - 昵称按界面显示形式匹配，也接受 `[U+XXXX]` 形式的 emoji 代码；
  - 不区分大小写，忽略首尾空格。
- **等级**：固定区间（全部 / Lv.1-3 / Lv.4-6 / Lv.7-9 / Lv.10+ / 无等级），
  以及「自定义」最低级 ~ 最高级输入。
- **标记**：全部 / 红 / 黄 / 绿 / 白；只在启用本地标记后显示。
- 多个条件同时生效时取交集（AND）。
- 输入/选择后立即刷新列表，不需要点“查询”。
- 提供「清除筛选」按钮。
- 底部显示“当前显示 X / 共 Y 人”。
- 筛选只影响参与者列表的显示，不改变已抓取的数据；
- 导出时如果筛选条件生效，弹窗让用户选择：
  - 导出全部用户；
  - 只导出当前筛选结果；
  - 取消导出。
  没有筛选时直接导出全部，不弹窗。
- 筛选后选中某一行，详情仍对应原来的用户，不会串行。
- 重新抓取或刷新参与者时清空筛选条件。

### 3.4 查用户

- 按用户名 / 用户ID / 昵称查询；
- 昵称输入框必须接受原始 Unicode（含 emoji）和 `[U+XXXX]` 代码；
- 两种写法等价：`🐉王一滋` 与 `[U+1F409]王一滋` 应查询同一用户；
- 输入框不得过滤/拦截输入法组合或 emoji 字符；
- 无法用输入法输入 emoji 时，可直接输入 `[U+XXXX]` 代码，程序解码后再查询；
- 输入框旁提供提示：“昵称支持 [U+XXXX] emoji 代码”；
- 提供「Emoji 代码」按钮：输入十六进制（如 `1F409`）后插入 `[U+1F409]`；
- 非法代码给出可理解的错误，不静默改成别的用户；
- Tk 界面统一用 `[U+XXXX]` 显示 emoji；
- Excel 和 Markdown 报告保留原始 emoji；
- 表格查看、参与者、查用户、日志使用同一显示规则；
- 界面必须提示：“界面用 [U+XXXX] 显示 emoji，导出 Excel 保留原样”；
- 显示昵称、用户名、ID、粉丝、关注数、发帖数；
- 显示关注贴吧、最近发言；
- 关注列表隐藏时，可按候选吧探测 `is_follow`（仅候选，不承诺全量枚举）；
- 支持复制和打开链接；
- 该页只做资料查看，不参与红绿灯判定。

### 3.5 本地标记与红绿灯开关

- **默认开启**：新安装或配置里没有 `risk_enabled` 时按开启处理；
- 保留「设置 → 通用 → 启用本地标记与红绿灯」开关，不删除；
- 用户显式关闭过（`risk_enabled=false`）则尊重关闭状态，不强制改回；
- 首次启动且开关开启时，显示一次提示：
  “仅用于本地记录，请勿用于挂人、骚扰或公开曝光”；
  提示不阻塞使用，确认后不再自动弹；
- 三级：绿色 / 黄色 / 红色；
- 命中优先级：红 > 黄 > 绿；
- 关闭后：
  - 参与者列表不显示标记列；
  - 表格不标色；
  - 「一键红绿灯」禁用；
  - 已保存的标记不删除；
  - 本地标记 Excel 导入/导出仍可在设置页使用；
- 导出主 Excel 不写标记；用户报告在开启时可包含标记；
- 支持 Excel 导入/导出；
- 导入时让用户选择模式：
  - **合并**：保留现有名单，导入项加入；冲突按 禁止 > 警告 > 安全 合并；
  - **覆盖**（默认）：只使用导入文件，替换现有名单；冲突同样按优先级合并；
- 导入前预览：
  - 现有条数；
  - 导入条数；
  - 冲突条数；
  - 合并/覆盖后的结果条数；
- 覆盖模式确认框写明“将替换现有 N 条”；
- 合并模式确认框写明“保留现有 M 条，导入 K 条”；
- 取消不改动现有名单；
- 导入成功后自动保存并刷新界面；
- 文件无有效行/格式错误：不导入，保留现有名单；
- 同一吧出现在多个等级时，按 禁止 > 警告 > 安全 合并，只保留最高级；
- 导入/保存去重、忽略空行；
- 吧名按既有规则归一化。

### 3.6 匿名抓取与关注增强（FR-008）

默认匿名抓取，不要求 Cookie，不再提供“免登录 / 登录”模式选择。

- 首次启动不再弹模式选择；
- 「抓取」页顶部不再放 `[免登录] [登录]` 切换器；
- 所有核心能力默认可用：
  - 楼层、完整楼中楼、参与者、等级、头衔；
  - 查用户基本资料、最近发言；
  - 隐藏关注候选探测；
  - 红绿灯只看本帖发言；
  - 导出、筛选、对比、报告、备份。

#### 3.6.1 关注增强（可选）

入口：「设置 → 高级 → 关注增强（需要 Cookie）」

- 默认关闭；
- 开启时必须提供登录凭据，支持两种输入方式：
  - **仅 BDUSS**（推荐，最小权限）；
  - **整段 Cookie**（兼容浏览器复制，内部只提取 BDUSS）；
- 两种方式能力相同；整段 Cookie 不额外增加功能；
- 整段 Cookie 里即使含 `STOKEN`，也不读取、不使用、不落盘；
- 「记住 BDUSS」默认勾选；
  - 勾选：用 Windows DPAPI 保存 BDUSS；
  - 取消：只在本次会话内存使用，退出即丢；
  - 整段 Cookie 也只保存 BDUSS，其他字段不落盘；
- 下次启动不因为“检测到 BDUSS”自动开启关注增强；
- 但恢复上次明确开启的状态：
  - 上次开启 + 已保存 BDUSS → 自动恢复开启；
  - 上次开启 + 没有 BDUSS → 强制关闭并提示；
  - 上次关闭 → 保持关闭；
- 启动时不强制联网校验 BDUSS；首次请求失败时提示并关闭关注增强；
- 第一次开启关注增强时，立即验证一次 BDUSS：
  - 成功：开启；
  - 明确无效/过期：保持关闭，提示重新填写；
  - 网络/验证码导致无法验证：保持关闭，提示“暂时无法验证，不代表 BDUSS 错误”；
  - 验证只请求一次，不循环重试；
  - 验证中按钮显示加载状态。
- Cookie 只用于读取对方**没有隐藏**的公开关注列表；
- 不改变抓取、楼中楼、导出等核心能力；
- 关闭后立即回到匿名行为，不需要重启；
- 不根据 Cookie 是否存在自动开启；
- 任何页面都不显示 Cookie/BDUSS 明文。

能力差异：

| 能力 | 默认匿名 | 关注增强开启 |
|---|---|---|
| 抓取 / 完整楼中楼 | ✅ | ✅ |
| 基本资料 / 最近发言 | ✅ | ✅ |
| 公开关注列表 | 🟡 部分 | ✅ 公开部分完整 |
| 隐藏关注完整列表 | ❌ | ❌ |
| 红绿灯：本帖发言 | ✅ | ✅ |
| 红绿灯：关注列表 | ❌ | ✅ |
| 隐藏关注标黄 | ❌ | ✅ |
| 吧务删除内容 | ❌ | ❌（已砍掉） |

#### 3.6.2 红绿灯规则

- 红绿灯开关默认开启，保留「设置 → 通用」开关；
- 一键红绿灯范围 = 参与者当前“帖子范围” + 当前筛选后可见用户：
  - 有筛选：只刷筛选后的人；
  - 无筛选：刷当前范围全部人；
  - 筛选后为空：提示并不启动；
  - 未刷到的人保持原标记不变；
- 红绿灯范围跟随参与者当前“帖子范围”：
  - 参与者选“全部帖子”：使用所有已抓帖子里的发言吧；
  - 参与者选单帖：只使用该帖里的发言吧；
  - 同一用户跨帖重复的吧去重；
  - 切换参与者范围后，下次一键红绿灯按新范围计算。
- 一键红绿灯默认只按发言：
  - 只使用当前范围内的发言吧（`user.bars`，含楼层和楼中楼）；
  - 只做本地 `classify`；
  - 不请求资料/关注；
  - 不触发隐藏关注标黄；
  - 没命中 → 白灯。
- 关注增强开启后，按钮旁出现「包含关注（慢）」勾选：
  - 默认不勾选；
  - 不勾选：仍只按发言，不发关注请求；
  - 勾选：数据来源 = 发言 + 最近发言 + 公开关注 + 精选/等级恢复/候选确认；
  - 勾选时可能很慢，界面必须提示；
  - 未开启关注增强时，该勾选禁用，并提示“先开启关注增强”；
  - 关注增强中途关闭，本次批量回退为仅发言并记录警告。
- 含关注时：
  - 命中禁止 → 红灯；
  - 隐藏关注且未命中禁止 → 黄灯 + ⚠；
  - 没有命中 → 白灯；
  - 单个用户关注查询失败：保留其发言判定，记录“关注查询失败”，不把隐藏规则强加上去；
- 批量错误策略：
  - 个体失败（资料缺失/无权限/单次超时）：记录并继续；
  - 验证码 / 429：立即停止批量；
  - 连续 3 次超时/网络错误：停止批量；
  - 停止时保留已完成标记，显示停止原因；
  - 不自动重试整个批量。
- 颜色优先级：红 > 黄 > 绿 > 白；
- 查用户页不参与红绿灯；
- 默认匿名批量只跑发言判定，不发资料/关注请求；
- 关注增强批量可查资料/关注；
- 按钮、日志、开关界面见 [ui-spec.md](ui-spec.md) UI-001 / UI-002 / UI-012。

#### 3.6.3 匿名查用户与关注列表

默认匿名查看单个用户资料时，允许**尝试**匿名读取公开关注列表，但必须遵守：

- 只尝试一次，短超时；失败不重试、不阻塞资料页；
- 成功：
  - 显示关注列表；
  - 标注“匿名尝试，可能不完整”；
  - 不得显示“完整关注列表”。
- 失败：
  - 资料页仍正常显示；
  - 关注区显示“未开启关注增强，关注列表不完整”；
  - 不把失败当成“没有关注”。
- 必须固定提示：
  “未开启关注增强：公开关注为匿名尝试，可能失败/不完整；
   要稳定读取请开启关注增强。隐藏关注仍不可见。”
- 匿名尝试结果不得用于红绿灯；
- 批量红绿灯期间不得因为选中行、刷新表格或缓存回填触发资料请求；
- 日志必须区分“一键红绿灯（仅发言）”和“查资料”。

#### 3.6.4 关注增强下的查用户加载方式

- 设置项：「设置 → 高级 → 查看用户资料时加载公开关注」；
- 适用范围：查用户页 + 参与者详情页；
- 选项：
  - 自动（默认）；
  - 手动；
- 仅在关注增强开启时生效；增强关闭时该项禁用/忽略；
- 两个页面共用同一设置和同一会话缓存；
- 自动：
  - 先显示基本资料，再加载公开关注；
  - 加载失败不影响基本资料；
  - 同一用户在同一会话内默认只自动加载一次；再次选中用缓存；
  - 提供「刷新关注」按钮可强制重新加载；
- 手动：
  - 不自动请求；
  - 显示「加载公开关注」按钮，点击才请求；
  - 加载失败提示，不把失败当成“没有关注”；
- 两种方式都不得显示“完整关注列表”；
- 隐藏关注仍不可完整枚举。

#### 3.6.5 资料查看与红绿灯解耦

- 查用户页只做资料展示，不参与红绿灯；
- 匿名尝试到的关注列表也不得反向影响红绿灯；

- 隐藏关注规则只在关注增强开启时生效。

### 3.10 配置备份 / 恢复（FR-012）

- 入口：「设置」→「通用」→「备份配置 / 恢复配置」；
- 备份范围固定为：所有非敏感设置 + 本地标记；
  - 包括关注增强、红绿灯、自动刷新、移除旧帖、恢复方式、保存/加密结果、加载方式等；
  - 不包括 Cookie / BDUSS / STOKEN；
  - 不包括最近结果数据库；

  - 单个 JSON（`贴吧统计配置_时间.json`）；
  - ZIP（内含 `config.json` 和 `README.txt`）；

- 立即生效的处理：
  - 关注增强：备份里若为开启，但当前没有有效 Cookie，则强制关闭并提示；
  - 红绿灯/加载方式/自动刷新/移除旧帖：立即更新界面和后续行为；
  - 保存最近结果：
    - 开启：立即开始保存当前结果；
    - 关闭：立即停止保存，并删除本地结果文件，当前内存结果保留；
  - 加密保存：
    - 开启：立即尝试把现有结果转为加密文件；失败则保留原文件、保持关闭并提示；
    - 关闭：立即尝试转回明文；失败则保留加密文件并提示；
  - 启动恢复方式：写入设置，下次启动按新方式执行；
  - 恢复配置不重启、不清空当前结果；
- 恢复不涉及 Cookie、快照、抓取历史；
- 恢复不删除、不覆盖 `last_result.db` / `last_result.enc`；
- 备份中未知设置项忽略，缺失项用默认值。

### 3.12 全量楼中楼（FR-014）

目标：默认匿名也能抓完整楼中楼；floor 失败且有关注增强 Cookie 时，才回退网页。

- 抓取深度：
  - 默认「全部」；
  - 可选「每层前 10 / 50 / 100 条」；
  - 选择限条数时，超过部分不再请求。
- 默认流程：
  1. `page` 接口取楼层 + 前 10 条预览；
  2. 对每层请求 `/c/f/pb/floor?cmd=302002`，按 `pn` 翻页；
  3. 按评论 `pid` 去重合并；
  4. 达到 `has_more=false` 或深度上限停止。
- 回退流程（仅当已开启关注增强并带 Cookie）：
  1. floor 失败（网络/超时/5xx/protobuf 错误/异常空结果）时，回退到
     `totalComment` + `/p/comment`；
  2. 回退时记录日志“第 X 层回退网页”；
  3. 两条路径结果按 `pid` 去重。
- 并发：
  - 默认 1（顺序）；
  - 设置中可调 1~3；
  - 并发越高越快，但风控风险越高，界面需提示。
- 失败处理：
  - 单层失败不终止整个帖子；
  - 保留该层前 10 条预览，并记录警告“该层楼中楼不完整”；
  - 重试 1~2 次后仍失败才回退/放弃。
- 保护上限：
  - 每层最多 50 页；
  - 单个帖子最多 2000 次楼中楼请求；
  - 超过上限停止并提示；
  - 支持中途停止；
- 抓取/批量运行中关闭窗口：
  - 弹窗确认“任务仍在进行，停止并退出？”；
  - 确认后停止任务，保存已完成部分（若开启保存结果），再退出；
  - 取消则继续；
  - 保存失败时提示，允许用户选择是否仍退出；
  - 不强制杀进程，避免结果文件损坏。
- 进度：
  - 显示“楼中楼：X/Y 层，已抓 N 条”；
  - 失败/回退逐层记录。
- 证据状态：
  - 匿名 floor 翻页已实测（见 protocol.md）；
  - 关注增强态 floor 回退尚未实测，实现前需补证据；
  - 回退逻辑属于设计，待实现时验证。

### 3.13 隐藏关注候选探测（FR-015）

  - 「查用户」页；
  - 「参与者」详情页。

  - 本帖发言吧；
  - 最近发言吧；
  - 本地标记中的吧。

  1. 汇总候选吧并去重；
  2. 排除已在公开关注/精选关注里的吧；
  3. 最多探测 30 个候选；
  4. 逐个调用 `get_user_forum_info(吧名, uid)`；

  - 手动触发，不自动跑；
  - 最多 30 个候选，单次探测；
  - 沿用请求间隔，可中途停止；
  - 结果只在当前会话缓存，不写入配置/备份；
  - 用户报告导出时可按当前关注表包含，并保留「来源」列；
  - 不做“遍历所有贴吧”。
- 错误：
  - 吧不存在/无权限：跳过该候选，继续；
  - 连续失败/被限流：停止并提示；
  - 用户无公开资料：提示无法探测。
- 证据：
  - 匿名 `get_user_forum_info` 已实测可返回 `is_follow`；
  - 隐藏用户 `priv_like=3` 实测；
  - 关注增强态行为未单独验证。

### 3.15 最近结果持久化

只保存“最近一次结果”，不做历史快照。

- 存储位置：`%APPDATA%\TiebaReplyStats\last_result.db`；
- 存储格式：SQLite，带 `schema_version`、`app_version`、`saved_at`；
- 表结构：
  - `meta(key, value)`：`schema_version`、`app_version`、`saved_at`；
  - `threads(tid, title, forum, source_url, fetched_at, payload_version, payload_json)`；
  - `tid` 为主键，一个帖子只保留一行；
  - 刷新成功时替换该 tid 的整行；
  - `payload_json` 存该帖的楼层、楼中楼、警告等完整数据；
  - 不建 floors/comments 独立表；
  - 不保存历史快照；
- 保存时机：
  - 每完成一个帖子后保存一次；
  - 用户停止时保存已完成部分；
  - 全部完成后再保存一次；
  - 保存采用“临时文件 + 原子替换”，失败不破坏旧文件；
- 启动时：
  - 恢复后只本地重算“仅发言”标记；
  - 不自动请求关注；
  - 关注增强标记不自动恢复，提示“关注标记需重新刷新”；
  - 如果存在有效结果，按设置处理：
    - **自动恢复**（默认）：直接加载；
    - **询问**：弹窗“恢复上次结果（时间）？”，提供：
      - 恢复；
      - 跳过（本次不加载，文件保留）；
      - 删除；
  - 状态栏/日志显示“已恢复上次结果（时间）”；
  - 恢复不发起网络请求，不自动开始抓取；
- 清空：
  - 「清空结果」同时删除内存结果和本地文件：`last_result.db` 或 `last_result.enc`；
  - 删除失败要提示，不能假装已清空；
- 数据范围：
  - 只存帖子、楼层、楼中楼、抓取元信息；
  - 不存 Cookie、BDUSS、STOKEN；
  - 不存本地标记（本地标记单独保存）；
- 版本/损坏：
  - 版本不兼容或文件损坏：不加载、保留文件、提示，从空白开始，不崩溃；
  - 不做自动迁移；
  - 用户再次保存新结果时，先把旧文件重命名为
    `last_result.incompatible-YYYYMMDD-HHMMSS.db`（加密文件同理），再写新文件；
  - 不直接删除旧文件；
  - 关于页显示旧不兼容文件数量、占用空间；
  - 提供「清理旧结果文件」，只删 `.incompatible-*`，不删当前结果；
  - 「清空所有本地数据」一并删除这些旧文件；
- 设置：
  - 「设置 → 高级 → 启动时恢复上次结果」：自动 / 询问，默认自动；
  - 「设置 → 高级 → 保存最近结果」默认开启；
  - 「设置 → 高级 → 加密保存最近结果」默认关闭；
- 加密保存（可选）：
  - 开启后文件为 `last_result.enc`，使用 Windows DPAPI（当前用户）加密；
  - 不以明文 SQLite 落盘；
  - 保存流程：临时 SQLite → DPAPI 加密 → 原子替换 → 清理临时文件；
  - 恢复流程：DPAPI 解密 → 内存/临时 SQLite → 读取 → 清理临时文件；
  - 关闭加密：改回 `last_result.db` 明文；
  - 切换加密状态时先确认，转换失败保留旧文件并提示，不丢数据；
  - DPAPI 只能当前 Windows 用户解密，换用户/换电脑无法恢复；
  - 加密开启/关闭只影响本地保存，不影响当前内存结果；
  - 关闭后，退出时删除本地结果；
  - 关闭不影响当前会话内存结果；
- 隐私：
  - 结果只在本机，不上传；
  - 文件位于当前 Windows 用户目录；
  - 不做多用户共享。

### 3.16 清空所有本地数据

- 关注增强关闭；
- 清空后立即生效，不要求重启：
  - 当前内存结果清空；

### 3.22 单实例与批量并发

- 软件只允许一个实例运行；
- 第二次启动：
  - 不新开窗口；
  - 聚焦已有窗口（最小化则恢复）；
  - 提示“软件已在运行”；
- 不支持多开，理由必须写清楚：
  - 同一 IP/账号仍受贴吧限流，多开不会更快；
  - 重复请求更容易触发安全验证；
  - 多个实例会争用结果数据库、加密文件和临时工作簿；
- 一键红绿灯支持并发 1~3：
  - 默认 1；
  - 设置位置：「设置 → 抓取行为 → 一键红绿灯并发」；
  - 并发共享统一请求间隔；
  - 并发越高越快，但风控风险越高，界面要提示；
  - 支持停止，停止后保留已处理标记；
- 勾选「包含关注」时：
  - 本次批量并发强制为 1；
  - 即使设置为 2/3，也降为串行；
  - 界面提示“关注查询较敏感，本次串行执行”；
  - 取消勾选后恢复原并发设置；
- 批量并发只用于一键红绿灯，不改变抓取页的楼中楼并发。

### 3.23 用户身份与去重

统一身份优先级：

```text
UID > portrait > 用户名 > 昵称
```

规则：

- UID 为 `0`、空、`None` 视为缺失；
- portrait 比较前去掉 `?t=...` 查询串；
- 同一 UID，即使昵称/用户名变了，也合并为同一人；
- 同一 UID 出现多个昵称时：
  - 以最新昵称为主；
  - 记录曾用昵称；
  - 表格显示“最新昵称（曾用：旧1、旧2）”，最多列 2 个，更多显示“等 N 个”；
  - Excel/报告增加“曾用昵称”列，分号分隔；
  - 曾用昵称按首次出现顺序、去重；
  - 无 UID 的匿名用户不推断曾用昵称；
- 同一 nickname 但 UID/portrait 不同，绝不合并；
- UID 缺失、portrait 存在时，用 portrait 作为身份；
- portrait 也缺失时，才用用户名；
- 用户名也缺失时，才用昵称兜底：
  - 用 `anon:昵称` 合并同一昵称；
  - 显示“匿名/可能同名”；
  - 不伪造 UID/用户名；
  - 同一昵称可能是不同人，报告/导出要提示“匿名合并，可能同名”；
- 昵称也为空时：
  - 每次发言单独作为“匿名（无法识别）”；
  - 不跨帖合并；
- 统计、对比、报告、查用户、红绿灯必须使用同一套身份键；
- 界面显示：昵称 + 用户名/ID；匿名兜底时标注“匿名”；
- 导出保留昵称、用户名、UID，匿名项不伪造 ID。

### 3.24 错误分类与恢复

统一错误目录，各模块复用同一套文案和处理策略。

| 类别 | 用户提示 | 自动重试 | 任务处理 | 日志 |
|---|---|---|---|---|
| 输入格式错误 | 指出哪一段不合法 | 否 | 阻止提交 | 否 |
| 验证码 / 安全验证 | 需要浏览器验证或更新 Cookie | 否 | 停止当前任务 | 是 |
| 403 / 412 | 访问被拒绝，可能需登录/Cookie | 否 | 停止当前任务 | 是 |
| 404 / 帖子不存在 | 帖子已删除或不可访问 | 否 | 跳过该帖，继续下一帖 | 是 |
| 429 / 限流 | 请求过快，请稍后或调大间隔 | 否 | 停止批量/当前任务 | 是 |
| 网络超时 / 断网 | 网络异常，检查连接 | 最多 2 次退避 | 失败后保留已完成 | 是 |
| 登录/BDUSS 失效 | 关注增强已关闭，请重填 | 否 | 关闭关注增强，核心继续 | 是 |
| 文件被占用 | 关闭 Excel/占用程序后重试 | 否 | 不删除、不覆盖 | 是 |
| 磁盘满/无权限 | 换位置或清理空间 | 否 | 停止保存/导出 | 是 |
| 结果文件损坏/版本不兼容 | 旧文件已保留，从空白开始 | 否 | 忽略旧文件 | 是 |
| 未预期异常 | 显示摘要，可复制诊断信息 | 否 | 保留已完成，停止当前操作 | 是 |

通用规则：

- 用户提示必须能指导下一步，不显示裸异常；
- 技术细节写日志，不写 Cookie/BDUSS/STOKEN；
- 验证码/429 不自动循环重试；
- 停止任务时保留已完成结果；
- 错误弹窗默认“确定”，破坏性操作默认“取消”。

### 3.25 高 DPI 与键盘操作

高 DPI：

- Windows 使用 Per-Monitor DPI Awareness；
- 支持 100% / 125% / 150% / 200% 缩放；
- 关键按钮、标签、日志、表格在 125%/150% 下不被截断；
- 最小窗口按逻辑单位计算，不按固定像素；
- 多显示器不同缩放时，窗口移动后重新适配；
- 不要求自定义字体缩放，但必须跟随系统缩放。

键盘：

- Tab 顺序按“输入 → 选项 → 主按钮 → 次按钮 → 表格”；
- Enter = 当前主操作（开始/查询/确认）；
- 多行文本框内 Enter 仍是换行，不触发主操作；
- Esc = 取消/关闭当前非破坏性对话框；
- 破坏性对话框默认焦点在“取消”；
- F1 = 打开使用说明；
- Ctrl+C = 复制当前表格选中行；
- Ctrl+A = 只选当前页；
- 焦点框必须可见，不能完全依赖鼠标。

### 3.26 升级与本地数据

- 免安装，原地升级：替换程序目录，不要求卸载；
- `%APPDATA%\TiebaReplyStats` 数据默认保留；
- 升级不自动删除：设置、BDUSS、本地标记、最近结果、日志；
- 设置：
  - 缺失项用默认值；
  - 未知项忽略；
  - 不因为版本变化清空设置；
- 结果：
  - schema 兼容则恢复；
  - 不兼容按既有规则保留/忽略，不覆盖；
- Cookie/BDUSS 使用 DPAPI，同一 Windows 用户升级后可继续用；
- 多版本共存时共用同一数据目录，单实例锁仍然生效；
- 不写注册表、不写系统目录；
- 卸载 = 删除程序目录；
- 删除程序目录不自动删除 `%APPDATA%\TiebaReplyStats`；
- 使用说明写清楚数据路径；
- 要清干净，先在「关于 → 清空所有本地数据」执行；
- 不提供自动删除数据的卸载脚本。

## 4. 非功能需求
