# 需求与边界

## 1. 背景

贴吧帖子页的楼层和楼中楼没有方便的批量导出工具。本项目面向需要统计“谁回复了多少、
发了什么”的个人用户，提供 Windows 桌面程序、命令行和 Android 版。

## 2. 目标用户

- 想导出某个帖子参与情况的普通用户；
- 需要查看参与者资料（关注吧、最近发言）的用户；
- 未来希望在手机上临时抓公开帖子的人（Android 暂缓）。

## 3. 功能需求

### 3.1 抓取

- 支持一个或多个帖子链接/帖子 ID；
- 自动识别总页数，逐页抓取主题楼层；
- 抓取楼中楼（登录模式：`totalComment` + `/p/comment`；免登录模式：客户端 protobuf，逐层翻页抓全）；
- 支持“最多页数”“是否抓楼中楼”“是否导出”等选项；
- 支持中途停止。

### 3.2 统计与导出

- 按用户汇总：楼层数、楼中楼数、合计、等级、头衔、首次出现楼层；
- 导出 Excel：总览、用户汇总、每帖工作表；
- 包含超链接、冻结首行、筛选、合计行。

### 3.3 参与者

- 列表展示所有参与者；
- 点选后显示：关注贴吧（含等级）、最近发言（日期/类型/贴吧/标题/内容）；
- 支持条数（5~1000）与日期范围；
- 支持一键批量刷新红绿灯（按用户设置条数与日期）；
- 红绿灯默认关闭；在「设置 → 通用」显式开启后，才显示红绿灯列和批量按钮。

#### 参与者筛选（FR-009）

在参与者列表上方增加一行筛选条：

- **关键词**：匹配昵称、用户名、用户 ID；
  - 昵称按界面显示形式匹配，也接受 `[U+XXXX]` 形式的 emoji 代码；
  - 不区分大小写，忽略首尾空格。
- **等级**：固定区间（全部 / Lv.1-3 / Lv.4-6 / Lv.7-9 / Lv.10+ / 无等级），
  以及「自定义」最低级 ~ 最高级输入。
- **标记**：全部 / 红 / 黄 / 绿 / 白；只在启用本地标记后显示。
- 多个条件同时生效时取交集（AND）。
- 输入/选择后立即刷新列表，不需要点“查询”。
- 提供「清除筛选」按钮。
- 底部显示“当前显示 X / 共 Y 人”。
- 筛选只影响参与者列表的显示，不改变已抓取的数据；
- 导出时如果筛选条件生效，弹窗让用户选择：
  - 导出全部用户；
  - 只导出当前筛选结果；
  - 取消导出。
  没有筛选时直接导出全部，不弹窗。
- 筛选后选中某一行，详情仍对应原来的用户，不会串行。
- 重新抓取或刷新参与者时清空筛选条件。

### 3.4 查用户

- 按用户名 / 用户ID / 昵称查询；
- 显示昵称、用户名、ID、粉丝、关注数、发帖数；
- 显示关注贴吧、最近发言；
- 关注列表隐藏时，可按候选吧探测 `is_follow`（仅候选，不承诺全量枚举）；
- 支持复制和打开链接；
- 该页只做资料查看，不参与红绿灯判定。

### 3.5 本地标记

- 默认关闭，必须在「设置 → 通用」显式开启；
- 首次开启弹一次提示：“仅用于本地记录，请勿用于挂人、骚扰或公开曝光”；
- 三级：绿色 / 黄色 / 红色；
- 命中优先级：红 > 黄 > 绿；
- 只有开启后才参与参与者红绿灯；导出不写标记；
- 支持 Excel 导入/导出；
- 关注列表隐藏的用户：命中红色仍为红；未命中红色时标黄并提示风险（仅登录模式）。

### 3.6 抓取模式（FR-008）

抓取前必须**显式选择**模式，禁止根据 Cookie 是否为空自动切换。

- **免登录模式（默认）**
  - 不读取、不使用 Cookie；
  - 只抓公开内容：楼层、完整楼中楼（逐层翻页）、参与者、等级；
  - 可查最近发言和基本资料，但关注列表可能不完整；
  - 红绿灯只按**本帖发言**判定，不查关注列表（免登录查不到完整关注，
    按关注判定会误伤）。
- **登录模式**
  - 必须提供包含 `BDUSS` 的 Cookie；
  - 推荐只填 `BDUSS=...`（最小权限，不交出 STOKEN）；
  - 也接受整段 Cookie（兼容性更好，但会包含 STOKEN 等更多字段）；
  - 完整楼中楼、关注列表、完整资料、一键红绿灯（发言 + 关注）；
  - `STOKEN` 仅吧务删除内容功能需要，普通抓取不要求；
  - 未提供 `BDUSS` 时阻止开始，提示“切换免登录模式”或“填写 Cookie”，
    **不得静默降级为免登录**。

模式规则：

- 模式选择持久化，默认免登录；
- 已保存 Cookie 时自动填入；模式保持上次选择，可在顶部切换；
- 免登录模式下 Cookie 输入框禁用，但保留已填内容；
- 切换模式不清空已抓结果，下一次抓取按新选择执行；
- 状态栏、日志、导出信息中标注本次模式。

模式选择入口：

- **首次启动**：弹一次“选择使用方式”对话框，两张卡片（免登录 / 登录），
  默认选中免登录，勾选“记住选择”；
- **之后启动**：不再弹窗，在「抓取」页顶部保留分段选择器
  `[免登录] [登录]`，旁边显示当前模式能力提示；
- 用户随时可切换；切换登录但无 Cookie 时，展开 Cookie 区并提示；
- Android 采用同样的“首次选择 + 顶部模式卡片”，不做登录墙。

红绿灯判定：

- **免登录**：只看本帖发言吧，`classify` 后按 禁止 > 警告 > 安全；
  没有命中就是白灯；不读取关注列表，不触发“隐藏关注标黄”规则。
- **登录**：发言吧 + 关注吧 + 隐藏恢复吧；保留“隐藏关注且未命中禁止 → 黄灯 + ⚠”。
- 模式下“一键红绿灯”都可用，但免登录只跑发言判定，不发资料请求。

能力矩阵：

| 功能 | 免登录 | 登录 |
|---|---|---|
| 楼层 | ✅ | ✅ |
| 楼中楼 | 完整（逐层翻页） | 完整 |
| 参与者 / 等级 | ✅ | ✅ |
| 导出 Excel | ✅ | ✅ |
| 查用户 | 基本（可能不完整） | 完整 |
| 关注列表 | 部分 | 公开部分完整 |
| 一键红绿灯 | ✅（仅发言） | ✅（发言 + 关注） |

> 注：桌面已实现免登录 floor 逐层翻页；Android 仍暂缓。

#### 3.6.1 一键红绿灯按钮与模式边界

按钮文案：

- 固定为 **“一键红绿灯”**，不追加“（仅发言）”等括号说明；
- 运行中固定为 **“停止查询”**；
- 停止中固定为 **“正在停止…”**；
- 按钮宽度必须容纳 5 个汉字，默认窗口和最小窗口下都不能出现半个括号或截断。

模式说明放在按钮外：

- 免登录：按钮旁或参与者提示区显示“仅发言判定”；
- 登录：显示“发言 + 关注”；
- 不允许把模式说明塞进按钮文案。

批量行为：

- **免登录**：
  - 只使用当前帖子已抓到的发言吧（`user.bars` / 楼层作者吧）；
  - 只做本地 `classify`，**不发起任何资料/关注请求**；
  - 不调用 `fetch_user_profile`、`get_follow_forums`、`get_user_forum_info`；
  - 不触发“隐藏关注标黄”；
  - 没有发言吧的用户按白灯处理。
- **登录**：
  - 可以查资料、公开关注、隐藏恢复；
  - 保留“隐藏关注且未命中禁止 → 黄灯 + ⚠”。
- 批量进度只显示人数，不显示“关注查询”字样；免登录日志应明确写“仅按发言判定”。

资料查看与红绿灯解耦：

- 免登录查看单个用户资料时，允许请求公开资料/公开关注用于展示；
- 但不得把这些结果用于一键红绿灯；
- 批量红绿灯期间不得因为选中行、刷新表格或缓存回填而触发资料请求；
- 日志必须区分“一键红绿灯（仅发言）”和“查资料”。

验收：

- 免登录一键红绿灯期间，网络日志中不得出现用户资料/关注接口；
- 免登录结果只可能来自本帖发言吧；
- 按钮在 840px 宽窗口下完整显示“一键红绿灯”；
- 登录模式行为不变。

#### 3.6.2 运行日志可见性

默认窗口下，运行日志必须可见，不能被下方窗口边缘或表单挤出。

布局要求：

- 日志区固定在「抓取」页底部，默认展开；
- 日志区最小高度 150px，约 8 行；
- 上方表单区域可滚动，窗口变小时优先压缩表单，不压缩日志到不可见；
- 默认窗口建议 980×820；屏幕工作区不足时按工作区高度自适应，但不能低于最小高度；
- 最小窗口 840×680 时，日志至少保留 6 行；
- 日志区可折叠，但默认展开；折叠后标题显示“运行日志（已折叠）”，不能完全消失；
- 运行中自动滚动到底部；用户手动上滚后不强制抢回焦点，除非切回底部。

验收：

- 1280×720、1366×768、1920×1080 三种工作区下，默认打开即可看到至少 6 行日志；
- 不最大化、不拖动窗口，也能看到最近一条错误；
- 日志滚动条可用。

### 3.7 Android（暂缓）

- 当前暂缓实施，先完成桌面版验收；
- 同一套 Python 核心；
- WebView 界面 + 本地 HTTP 服务；
- 暂定范围：模式选择、免登录红绿灯（仅发言）、查用户、导出；
- 暂定不做：批量红绿灯、本地标记 Excel 导入导出、快照。

### 3.8 多帖参与者对比（FR-010）

- 入口：「表格查看」→「参与者对比」子表；
- 列出当前已抓帖子，勾选至少 2 个；
- 只使用已抓数据，不触发网络请求；
- 身份匹配：用户 ID → 用户名 → 昵称；
- 同一帖子内同一用户只算一次；
- 固定四种模式：
  - **交集**：在所有选中帖子都出现；
  - **并集**：在任意选中帖子出现；
  - **仅在 A**：在 A 出现，且不在其他任何选中帖出现；
  - **A − B**：在 A 出现，且不在 B 出现（其余选中帖忽略）。
- A、B 为勾选顺序的前两个帖子，界面显示帖子标题，避免“A 是谁”；
- 结果列：昵称、用户名、用户 ID、各帖计数、合计、类型；
- 支持排序、复制、导出当前对比结果；
- 少于 2 个帖子时提示，不生成空表；
- 对比结果不受参与者筛选影响。

### 3.9 单用户报告导出（FR-011）

- 入口：
  - 「查用户」页导出报告；
  - 「参与者」页选中某人，右键导出此人报告。
- 输出两份文件，同目录、同文件名：
  - `用户报告_昵称_用户ID_时间.xlsx`
  - `用户报告_昵称_用户ID_时间.md`
- Excel 工作表：
  - 基本信息：昵称、用户名、ID、等级、粉丝、关注数、发帖数、抓取模式、导出时间；
  - 关注贴吧：吧名、等级、是否隐藏恢复；
  - 最近发言：日期、类型、贴吧、标题、内容、链接；
  - 本帖参与：楼层数、楼中楼数、合计、首次出现楼层；
  - 本地标记：仅在启用时写入颜色和命中吧名。
- Markdown 包含同样内容，链接可点击，适合贴到聊天/文档；
- 文件名中的 emoji 用 `[U+XXXX]` 或用户 ID 替代，避免非法字符；
- 免登录时关注表标注“可能不完整”；
- 报告不包含 Cookie；
- 本地标记关闭时不写标记。

### 3.10 配置备份 / 恢复（FR-012）

- 入口：「设置」→「通用」→「备份配置 / 恢复配置」；
- 备份范围固定为：通用设置、模式、红绿灯开关、本地标记；
- **不包含 Cookie**；
- 支持两种格式：
  - 单个 JSON（`贴吧统计配置_时间.json`）；
  - ZIP（内含 `config.json` 和 `README.txt`）；
- JSON 顶层包含 `schema_version`、`kind`、`exported_at`、`settings`、`blacklist`；
- 恢复流程：
  1. 选择 `.json` 或 `.zip`；
  2. 预览模式、本地标记数量、导出时间；
  3. 提示会覆盖当前设置和本地标记；
  4. 自动生成当前配置的临时备份；
  5. 确认后写入；
  6. 提示“重启后完全生效”。
- 非法/损坏/版本不支持的文件：只提示，不覆盖现有配置；
- 恢复不涉及 Cookie、快照、抓取历史。

### 3.11 吧务删除内容（只读，FR-013）

前提：登录模式 + 吧务权限 + `STOKEN`。

- 入口：独立「吧务」标签；
- 输入：
  - 吧名（只能是自己管理的吧）；
  - 用户：用户名 / 用户 ID / 昵称；
  - 可选日期范围；
  - 页码。
- STOKEN 来源：
  - 登录 Cookie 是整段粘贴时，自动解析其中的 STOKEN；
  - 吧务页只显示“已检测到 STOKEN”，不显示具体值；
  - 没检测到时，吧务页提供“手动补充 STOKEN”输入框（密码框）；
  - 手动补充的值只在本机 DPAPI 保存，不写日志、不导出、不进配置备份；
  - 任何页面都不显示 STOKEN 明文。
- 流程：
  1. 解析用户 ID；
  2. 调 `get_recovers` 拉取该用户被删的回复/主题；
  3. 列表展示；
  4. 选中一条，调 `get_recover_info` 取标题和正文详情。
- 列表字段：
  - 类型（主题 / 回复）；
  - 标题、内容摘要；
  - 作者；
  - 删除/操作时间；
  - 操作人；
  - 操作类型；
  - tid / pid；
  - 是否屏蔽。
- 详情：
  - 标题、正文、作者、tid/pid；
  - 只能查看，不提供恢复/删除/屏蔽。
- 权限与错误：
  - 不是吧务 → 明确提示“没有该吧的吧务权限”；
  - 缺 STOKEN → 提示去「设置 → 账号」填写；
  - 无结果 → 提示“没有查到可恢复的删除内容”，不一定是没删。
- 限制：
  - 只覆盖吧务后台保留期内、且可恢复的删除内容；
  - 系统删帖、过期内容、其他吧的内容不保证能查；
  - 不支持全吧删除日志（本期只做按用户）。
- 安全：
  - STOKEN 单独保存，DPAPI 加密；
  - 不写入日志、导出、配置备份；
  - 查询只读，绝不调用 `recover` / `del_*`。

### 3.12 全量楼中楼（FR-014）

目标：免登录也能抓完整楼中楼；登录模式优先走 floor 接口，失败回退网页。

- 抓取深度：
  - 默认「全部」；
  - 可选「每层前 10 / 50 / 100 条」；
  - 选择限条数时，超过部分不再请求。
- 免登录流程：
  1. `page` 接口取楼层 + 前 10 条预览；
  2. 对每层请求 `/c/f/pb/floor?cmd=302002`，按 `pn` 翻页；
  3. 按评论 `pid` 去重合并；
  4. 达到 `has_more=false` 或深度上限停止。
- 登录流程：
  1. 优先走 floor 接口；
  2. floor 失败（网络/超时/5xx/protobuf 错误/异常空结果）时，回退到现有网页
     `totalComment` + `/p/comment`；
  3. 回退时记录日志“第 X 层回退网页”；
  4. 两条路径结果按 `pid` 去重。
- 并发：
  - 默认 1（顺序）；
  - 设置中可调 1~3；
  - 并发越高越快，但风控风险越高，界面需提示。
- 失败处理：
  - 单层失败不终止整个帖子；
  - 保留该层前 10 条预览，并记录警告“该层楼中楼不完整”；
  - 重试 1~2 次后仍失败才回退/放弃。
- 保护上限：
  - 每层最多 50 页；
  - 单个帖子最多 2000 次楼中楼请求；
  - 超过上限停止并提示；
  - 支持中途停止。
- 进度：
  - 显示“楼中楼：X/Y 层，已抓 N 条”；
  - 失败/回退逐层记录。
- 证据状态：
  - 匿名 floor 翻页已实测（见 protocol.md）；
  - 登录态 floor 行为尚未实测，实现前需补证据；
  - 回退逻辑属于设计，待实现时验证。

### 3.13 隐藏关注候选探测（FR-015）

前提：对方关注列表隐藏（`followed_private` 或 `priv_like == 3`）。

- 入口：
  - 「查用户」页；
  - 「参与者」详情页。
  - 仅在检测到关注隐藏时显示「探测候选关注」按钮。
- 候选吧来源（只取这些，不允许自由输入或全站遍历）：
  - 本帖发言吧；
  - 最近发言吧；
  - 本地标记中的吧。
- 流程：
  1. 汇总候选吧并去重；
  2. 排除已在公开关注/精选关注里的吧；
  3. 最多探测 30 个候选；
  4. 逐个调用 `get_user_forum_info(吧名, uid)`；
  5. `is_follow=True` 的加入关注表。
- 展示：
  - 关注表增加「来源」列：公开 / 精选 / 等级恢复 / 候选确认；
  - 候选确认的行标注「推断」，并提示“只验证了候选吧，仍可能不完整”；
  - 不能显示成“完整关注列表”。
- 红绿灯：
  - 候选确认的 `is_follow=True` 可参与命中判定；
  - 但“关注列表隐藏”风险规则仍保留：未命中禁止时仍标黄 + ⚠。
- 限制：
  - 手动触发，不自动跑；
  - 最多 30 个候选，单次探测；
  - 沿用请求间隔，可中途停止；
  - 结果只在当前会话缓存，不写入配置/备份；
  - 用户报告导出时可按当前关注表包含，并保留「来源」列；
  - 不做“遍历所有贴吧”。
- 错误：
  - 吧不存在/无权限：跳过该候选，继续；
  - 连续失败/被限流：停止并提示；
  - 用户无公开资料：提示无法探测。
- 证据：
  - 匿名 `get_user_forum_info` 已实测可返回 `is_follow`；
  - 隐藏用户 `priv_like=3` 实测；
  - 登录态行为未单独验证。

### 3.14 凭据分级与能力边界

把“Cookie”拆成三级，避免把“登录”和“吧务权限”混为一谈：

1. **无凭据（免登录）**：不读取、不发送 Cookie；
2. **登录凭据（BDUSS）**：证明登录账号；
3. **吧务凭据（STOKEN + 吧务权限）**：只用于吧务删除内容，只读。

#### 3.14.1 能力矩阵

| 能力 | 无 Cookie | 有 BDUSS | 登录 + STOKEN + 吧务权限 |
|---|---|---|---|
| 抓楼层 / 翻页 | ✅ | ✅ | ✅ |
| 楼中楼全量（floor） | ✅ | ✅ | ✅ |
| 参与者 / 等级 / 头衔 | ✅ | ✅ | ✅ |
| 查用户基本资料 | 🟡 有限 | ✅ 较完整 | ✅ |
| 最近发言 | ✅ | ✅ | ✅ |
| 关注列表（公开部分） | 🟡 部分 | ✅ 公开部分完整 | ✅ |
| 关注列表（隐藏部分） | ❌ 不可完整枚举 | ❌ 仍不可完整枚举 | ❌ |
| 隐藏关注候选探测 | ✅ | ✅ | ✅ |
| 隐藏关注恢复（等级/精选） | 🟡 可能不全 | 🟡 可能不全 | 🟡 |
| 红绿灯：本帖发言 | ✅ | ✅ | ✅ |
| 红绿灯：关注列表 | ❌ | ✅ | ✅ |
| 吧务删除内容（只读） | ❌ | ❌ | ✅ |
| 导出 / 筛选 / 对比 / 报告 / 备份 | ✅ | ✅ | ✅ |
| 发帖 / 回复 / 关注 / 签到 | ❌ | ❌ | ❌ |
| 绕过验证码 / 隐私 / 删帖 | ❌ | ❌ | ❌ |

#### 3.14.2 不需要 Cookie 的能力（产品承诺）

- 公开帖子的楼层、完整楼中楼；
- 参与者统计、等级、头衔；
- 基本资料、最近发言；
- 隐藏关注候选探测；
- 红绿灯的“本帖发言”判定；
- 导出、筛选、多帖对比、用户报告、配置备份。

免登录不是“残废模式”，核心抓取和导出必须完整可用。

#### 3.14.3 需要 Cookie 的能力

- 登录身份；
- 登录后才可见的资料字段；
- 公开关注列表的完整读取；
- 一键红绿灯的“关注列表”判定；
- 登录态的网页回退路径。

#### 3.14.4 需要 STOKEN 的能力

- 只读的吧务删除内容；
- 还必须同时具备：
  - 登录 Cookie（BDUSS）；
  - 吧务权限；
  - 未过期的 STOKEN。

三者缺一不可。STOKEN 不是“更高级的登录”，只是敏感操作令牌。

#### 3.14.5 Cookie 也不能做到

- 不能完整枚举隐藏关注；
- 不能查看对方设为私密的内容；
- 不能恢复/删除/屏蔽吧务内容（本软件只读）；
- 不能绕过验证码、封禁、限流；
- 不能保证资料字段一定可见。

#### 3.14.6 产品规则

- 默认免登录，禁止按 Cookie 是否存在自动切换；
- 免登录模式绝不发送 Cookie；
- Cookie 存在不等于有吧务权限；
- 任何页面都不显示 Cookie/BDUSS/STOKEN 明文；
- 宣传时不得说“必须登录才能抓楼中楼”；
- 宣传时不得说“登录就能看完整隐藏关注”；
- 吧务功能必须标注“只读、需吧务权限”。

## 4. 非功能需求

- Windows 版为免安装目录，双击 exe 即可；
- 不要求目标机器安装 Python；
- 请求间隔可配置，默认 ≥0.3 秒，避免触发验证；
- Cookie 本地保存：Windows 使用 DPAPI，Android 存 App 私有目录；
- 日志不得输出 Cookie/BDUSS；
- 抓取失败要给出可理解的错误（验证、删帖、网络）；
- 支持离线自测（fixtures），不依赖网络。

## 5. 明确不做

- 不提供贴吧发帖/回复/签到等写操作；
- 不自动登录、不绕过验证码；
- 不承诺完整枚举隐藏关注列表；
- 不提供官方 API 或数据合作；
- 不做多用户 SaaS、不做公网服务。

## 6. 验收标准

- `python tests/selftest.py` 全部通过；
- 无 Cookie 能抓一个公开帖子并导出 Excel；
- 无 Cookie 能抓完整楼中楼；有 Cookie 能查公开关注与登录资料；
- 有 STOKEN + 吧务权限能查只读删除内容；
- 桌面 exe `--selftest` 返回 0；
- Android APK 能启动、抓取、导出（真机验证）。
