# 需求与边界

## 1. 背景

贴吧帖子页的楼层和楼中楼没有方便的批量导出工具。本项目面向需要统计“谁回复了多少、
发了什么”的个人用户，提供 Windows 桌面程序、命令行和 Android 版。

## 2. 目标用户

- 想导出某个帖子参与情况的普通用户；
- 需要查看参与者资料（关注吧、最近发言）的用户；
- 未来希望在手机上临时抓公开帖子的人（Android 暂缓）。

## 3. 功能需求

### 3.1 抓取

- 支持一个或多个帖子链接/帖子 ID；
- 自动识别总页数，逐页抓取主题楼层；
- 抓取楼中楼（登录模式：`totalComment` + `/p/comment`；免登录模式：客户端 protobuf，每层前 10 条）；
- 支持“最多页数”“是否抓楼中楼”“是否导出”等选项；
- 支持中途停止。

### 3.2 统计与导出

- 按用户汇总：楼层数、楼中楼数、合计、等级、头衔、首次出现楼层；
- 导出 Excel：总览、用户汇总、每帖工作表；
- 包含超链接、冻结首行、筛选、合计行。

### 3.3 参与者

- 列表展示所有参与者；
- 点选后显示：关注贴吧（含等级）、最近发言（日期/类型/贴吧/标题/内容）；
- 支持条数（5~1000）与日期范围；
- 支持一键批量刷新红绿灯（按用户设置条数与日期）；
- 红绿灯默认关闭；在「设置 → 通用」显式开启后，才显示红绿灯列和批量按钮。

#### 参与者筛选（FR-009）

在参与者列表上方增加一行筛选条：

- **关键词**：匹配昵称、用户名、用户 ID；
  - 昵称按界面显示形式匹配，也接受 `[U+XXXX]` 形式的 emoji 代码；
  - 不区分大小写，忽略首尾空格。
- **等级**：固定区间（全部 / Lv.1-3 / Lv.4-6 / Lv.7-9 / Lv.10+ / 无等级），
  以及「自定义」最低级 ~ 最高级输入。
- **标记**：全部 / 红 / 黄 / 绿 / 白；只在启用本地标记后显示。
- 多个条件同时生效时取交集（AND）。
- 输入/选择后立即刷新列表，不需要点“查询”。
- 提供「清除筛选」按钮。
- 底部显示“当前显示 X / 共 Y 人”。
- 筛选只影响参与者列表的显示，不改变已抓取的数据；
- 导出时如果筛选条件生效，弹窗让用户选择：
  - 导出全部用户；
  - 只导出当前筛选结果；
  - 取消导出。
  没有筛选时直接导出全部，不弹窗。
- 筛选后选中某一行，详情仍对应原来的用户，不会串行。
- 重新抓取或刷新参与者时清空筛选条件。

### 3.4 查用户

- 按用户名 / 用户ID / 昵称查询；
- 显示昵称、用户名、ID、粉丝、关注数、发帖数；
- 显示关注贴吧、最近发言；
- 支持复制和打开链接；
- 该页只做资料查看，不参与红绿灯判定。

### 3.5 本地标记

- 默认关闭，必须在「设置 → 通用」显式开启；
- 首次开启弹一次提示：“仅用于本地记录，请勿用于挂人、骚扰或公开曝光”；
- 三级：绿色 / 黄色 / 红色；
- 命中优先级：红 > 黄 > 绿；
- 只有开启后才参与参与者红绿灯；导出不写标记；
- 支持 Excel 导入/导出；
- 关注列表隐藏的用户：命中红色仍为红；未命中红色时标黄并提示风险（仅登录模式）。

### 3.6 抓取模式（FR-008）

抓取前必须**显式选择**模式，禁止根据 Cookie 是否为空自动切换。

- **免登录模式（默认）**
  - 不读取、不使用 Cookie；
  - 只抓公开内容：楼层、每层前 10 条楼中楼、参与者、等级；
  - 可查最近发言和基本资料，但关注列表可能不完整；
  - 红绿灯只按**本帖发言**判定，不查关注列表（免登录查不到完整关注，
    按关注判定会误伤）。
- **登录模式**
  - 必须提供包含 `BDUSS` 的 Cookie（整段粘贴最稳；只贴 `BDUSS=...` 也可）；
  - 完整楼中楼、关注列表、完整资料、一键红绿灯（发言 + 关注）；
  - `STOKEN` 仅吧务删除内容功能需要，普通抓取不要求；
  - 未提供 `BDUSS` 时阻止开始，提示“切换免登录模式”或“填写 Cookie”，
    **不得静默降级为免登录**。

模式规则：

- 模式选择持久化，默认免登录；
- 已保存 Cookie 时自动填入；模式保持上次选择，可在顶部切换；
- 免登录模式下 Cookie 输入框禁用，但保留已填内容；
- 切换模式不清空已抓结果，下一次抓取按新选择执行；
- 状态栏、日志、导出信息中标注本次模式。

模式选择入口：

- **首次启动**：弹一次“选择使用方式”对话框，两张卡片（免登录 / 登录），
  默认选中免登录，勾选“记住选择”；
- **之后启动**：不再弹窗，在「抓取」页顶部保留分段选择器
  `[免登录] [登录]`，旁边显示当前模式能力提示；
- 用户随时可切换；切换登录但无 Cookie 时，展开 Cookie 区并提示；
- Android 采用同样的“首次选择 + 顶部模式卡片”，不做登录墙。

红绿灯判定：

- **免登录**：只看本帖发言吧，`classify` 后按 禁止 > 警告 > 安全；
  没有命中就是白灯；不读取关注列表，不触发“隐藏关注标黄”规则。
- **登录**：发言吧 + 关注吧 + 隐藏恢复吧；保留“隐藏关注且未命中禁止 → 黄灯 + ⚠”。
- 模式下“一键红绿灯”都可用，但免登录只跑发言判定，不发资料请求。

能力矩阵：

| 功能 | 免登录 | 登录 |
|---|---|---|
| 楼层 | ✅ | ✅ |
| 楼中楼 | 每层前 10 条 | 完整 |
| 参与者 / 等级 | ✅ | ✅ |
| 导出 Excel | ✅ | ✅ |
| 查用户 | 基本（可能不完整） | 完整 |
| 关注列表 | 部分 | 公开部分完整 |
| 一键红绿灯 | ✅（仅发言） | ✅（发言 + 关注） |

### 3.7 Android（暂缓）

- 当前暂缓实施，先完成桌面版验收；
- 同一套 Python 核心；
- WebView 界面 + 本地 HTTP 服务；
- 暂定范围：模式选择、免登录红绿灯（仅发言）、查用户、导出；
- 暂定不做：批量红绿灯、本地标记 Excel 导入导出、快照。

### 3.8 多帖参与者对比（FR-010）

- 入口：「表格查看」→「参与者对比」子表；
- 列出当前已抓帖子，勾选至少 2 个；
- 只使用已抓数据，不触发网络请求；
- 身份匹配：用户 ID → 用户名 → 昵称；
- 同一帖子内同一用户只算一次；
- 固定四种模式：
  - **交集**：在所有选中帖子都出现；
  - **并集**：在任意选中帖子出现；
  - **仅在 A**：在 A 出现，且不在其他任何选中帖出现；
  - **A − B**：在 A 出现，且不在 B 出现（其余选中帖忽略）。
- A、B 为勾选顺序的前两个帖子，界面显示帖子标题，避免“A 是谁”；
- 结果列：昵称、用户名、用户 ID、各帖计数、合计、类型；
- 支持排序、复制、导出当前对比结果；
- 少于 2 个帖子时提示，不生成空表；
- 对比结果不受参与者筛选影响。

### 3.9 单用户报告导出（FR-011）

- 入口：
  - 「查用户」页导出报告；
  - 「参与者」页选中某人，右键导出此人报告。
- 输出两份文件，同目录、同文件名：
  - `用户报告_昵称_用户ID_时间.xlsx`
  - `用户报告_昵称_用户ID_时间.md`
- Excel 工作表：
  - 基本信息：昵称、用户名、ID、等级、粉丝、关注数、发帖数、抓取模式、导出时间；
  - 关注贴吧：吧名、等级、是否隐藏恢复；
  - 最近发言：日期、类型、贴吧、标题、内容、链接；
  - 本帖参与：楼层数、楼中楼数、合计、首次出现楼层；
  - 本地标记：仅在启用时写入颜色和命中吧名。
- Markdown 包含同样内容，链接可点击，适合贴到聊天/文档；
- 文件名中的 emoji 用 `[U+XXXX]` 或用户 ID 替代，避免非法字符；
- 免登录时关注表标注“可能不完整”；
- 报告不包含 Cookie；
- 本地标记关闭时不写标记。

### 3.10 配置备份 / 恢复（FR-012）

- 入口：「设置」→「通用」→「备份配置 / 恢复配置」；
- 备份范围固定为：通用设置、模式、红绿灯开关、本地标记；
- **不包含 Cookie**；
- 支持两种格式：
  - 单个 JSON（`贴吧统计配置_时间.json`）；
  - ZIP（内含 `config.json` 和 `README.txt`）；
- JSON 顶层包含 `schema_version`、`kind`、`exported_at`、`settings`、`blacklist`；
- 恢复流程：
  1. 选择 `.json` 或 `.zip`；
  2. 预览模式、本地标记数量、导出时间；
  3. 提示会覆盖当前设置和本地标记；
  4. 自动生成当前配置的临时备份；
  5. 确认后写入；
  6. 提示“重启后完全生效”。
- 非法/损坏/版本不支持的文件：只提示，不覆盖现有配置；
- 恢复不涉及 Cookie、快照、抓取历史。

### 3.11 吧务删除内容（只读，FR-013）

前提：登录模式 + 吧务权限 + `STOKEN`。

- 入口：独立「吧务」标签；
- 输入：
  - 吧名（只能是自己管理的吧）；
  - 用户：用户名 / 用户 ID / 昵称；
  - 可选日期范围；
  - 页码。
- STOKEN 来源：
  - 登录 Cookie 是整段粘贴时，自动解析其中的 STOKEN；
  - 吧务页只显示“已检测到 STOKEN”，不显示具体值；
  - 没检测到时，吧务页提供“手动补充 STOKEN”输入框（密码框）；
  - 手动补充的值只在本机 DPAPI 保存，不写日志、不导出、不进配置备份；
  - 任何页面都不显示 STOKEN 明文。
- 流程：
  1. 解析用户 ID；
  2. 调 `get_recovers` 拉取该用户被删的回复/主题；
  3. 列表展示；
  4. 选中一条，调 `get_recover_info` 取标题和正文详情。
- 列表字段：
  - 类型（主题 / 回复）；
  - 标题、内容摘要；
  - 作者；
  - 删除/操作时间；
  - 操作人；
  - 操作类型；
  - tid / pid；
  - 是否屏蔽。
- 详情：
  - 标题、正文、作者、tid/pid；
  - 只能查看，不提供恢复/删除/屏蔽。
- 权限与错误：
  - 不是吧务 → 明确提示“没有该吧的吧务权限”；
  - 缺 STOKEN → 提示去「设置 → 账号」填写；
  - 无结果 → 提示“没有查到可恢复的删除内容”，不一定是没删。
- 限制：
  - 只覆盖吧务后台保留期内、且可恢复的删除内容；
  - 系统删帖、过期内容、其他吧的内容不保证能查；
  - 不支持全吧删除日志（本期只做按用户）。
- 安全：
  - STOKEN 单独保存，DPAPI 加密；
  - 不写入日志、导出、配置备份；
  - 查询只读，绝不调用 `recover` / `del_*`。

## 4. 非功能需求

- Windows 版为免安装目录，双击 exe 即可；
- 不要求目标机器安装 Python；
- 请求间隔可配置，默认 ≥0.3 秒，避免触发验证；
- Cookie 本地保存：Windows 使用 DPAPI，Android 存 App 私有目录；
- 日志不得输出 Cookie/BDUSS；
- 抓取失败要给出可理解的错误（验证、删帖、网络）；
- 支持离线自测（fixtures），不依赖网络。

## 5. 明确不做

- 不提供贴吧发帖/回复/签到等写操作；
- 不自动登录、不绕过验证码；
- 不承诺完整枚举隐藏关注列表；
- 不提供官方 API 或数据合作；
- 不做多用户 SaaS、不做公网服务。

## 6. 验收标准

- `python tests/selftest.py` 全部通过；
- 无 Cookie 能抓一个公开帖子并导出 Excel；
- 有 Cookie 能抓楼中楼、查用户资料；
- 桌面 exe `--selftest` 返回 0；
- Android APK 能启动、抓取、导出（真机验证）。
