# 需求与边界

## 1. 背景

贴吧帖子页的楼层和楼中楼没有方便的批量导出工具。本项目面向需要统计“谁回复了多少、
发了什么”的个人用户，提供 Windows 桌面程序、命令行和 Android 版。

## 2. 目标用户

- 想导出某个帖子参与情况的普通用户；
- 需要查看参与者资料（关注吧、最近发言）的用户；
- 未来希望在手机上临时抓公开帖子的人（Android 暂缓）。

## 3. 功能需求

### 3.1 抓取

- 支持一个或多个帖子链接/帖子 ID；
- 多个帖子按 tid 去重；重复链接只抓一次；
- 再次抓取时，已存在的帖子默认跳过，只抓新增帖子；
- 用户可对单个帖子显式点“重新抓取”，或清空后重抓；
- 跳过/新增/重抓都要在日志中说明；
- 自动识别总页数，逐页抓取主题楼层；
- 抓取楼中楼：默认用客户端 protobuf 逐层翻页；floor 失败且有关注增强 Cookie 时，回退网页 `totalComment` + `/p/comment`；
- 支持“最多页数”“是否抓楼中楼”“是否导出”等选项；
- 支持中途停止。

### 3.2 统计与导出

- 按用户汇总：楼层数、楼中楼数、合计、等级、头衔、首次出现楼层；
- 表格查看顶部提供“帖子切换”，可选每个已抓帖子；
- 默认显示第一个帖子，切换后表头和明细同步切换；
- 导出 Excel 默认包含全部已抓帖子；
- 包含超链接、冻结首行、筛选、合计行。

### 3.3 参与者

- 列表展示参与者；
- 顶部提供“帖子范围”：全部帖子 / 单个帖子；
- 默认“全部帖子”，切换单帖后只统计该帖参与者；
- 点选后显示：关注贴吧（含等级）、最近发言（日期/类型/贴吧/标题/内容）；
- 支持条数（5~1000）与日期范围；
- 支持一键批量刷新红绿灯（按用户设置条数与日期）；
- 红绿灯默认开启；可在「设置 → 通用」关闭，关闭后不显示红绿灯列并禁用批量按钮。

#### 参与者筛选（FR-009）

在参与者列表上方增加一行筛选条：

- **关键词**：匹配昵称、用户名、用户 ID；
  - 昵称按界面显示形式匹配，也接受 `[U+XXXX]` 形式的 emoji 代码；
  - 不区分大小写，忽略首尾空格。
- **等级**：固定区间（全部 / Lv.1-3 / Lv.4-6 / Lv.7-9 / Lv.10+ / 无等级），
  以及「自定义」最低级 ~ 最高级输入。
- **标记**：全部 / 红 / 黄 / 绿 / 白；只在启用本地标记后显示。
- 多个条件同时生效时取交集（AND）。
- 输入/选择后立即刷新列表，不需要点“查询”。
- 提供「清除筛选」按钮。
- 底部显示“当前显示 X / 共 Y 人”。
- 筛选只影响参与者列表的显示，不改变已抓取的数据；
- 导出时如果筛选条件生效，弹窗让用户选择：
  - 导出全部用户；
  - 只导出当前筛选结果；
  - 取消导出。
  没有筛选时直接导出全部，不弹窗。
- 筛选后选中某一行，详情仍对应原来的用户，不会串行。
- 重新抓取或刷新参与者时清空筛选条件。

### 3.4 查用户

- 按用户名 / 用户ID / 昵称查询；
- 昵称输入框必须接受原始 Unicode（含 emoji）和 `[U+XXXX]` 代码；
- 两种写法等价：`🐉王一滋` 与 `[U+1F409]王一滋` 应查询同一用户；
- 输入框不得过滤/拦截输入法组合或 emoji 字符；
- 无法用输入法输入 emoji 时，可直接输入 `[U+XXXX]` 代码，程序解码后再查询；
- 输入框旁提供提示：“昵称支持 [U+XXXX] emoji 代码”；
- 提供「Emoji 代码」按钮：输入十六进制（如 `1F409`）后插入 `[U+1F409]`；
- 非法代码给出可理解的错误，不静默改成别的用户；
- 显示昵称时可继续用 `[U+XXXX]` 形式，避免字体缺字；
- 显示昵称、用户名、ID、粉丝、关注数、发帖数；
- 显示关注贴吧、最近发言；
- 关注列表隐藏时，可按候选吧探测 `is_follow`（仅候选，不承诺全量枚举）；
- 支持复制和打开链接；
- 该页只做资料查看，不参与红绿灯判定。

### 3.5 本地标记与红绿灯开关

- **默认开启**：新安装或配置里没有 `risk_enabled` 时按开启处理；
- 保留「设置 → 通用 → 启用本地标记与红绿灯」开关，不删除；
- 用户显式关闭过（`risk_enabled=false`）则尊重关闭状态，不强制改回；
- 首次启动且开关开启时，显示一次提示：
  “仅用于本地记录，请勿用于挂人、骚扰或公开曝光”；
  提示不阻塞使用，确认后不再自动弹；
- 三级：绿色 / 黄色 / 红色；
- 命中优先级：红 > 黄 > 绿；
- 关闭后：
  - 参与者列表不显示标记列；
  - 表格不标色；
  - 「一键红绿灯」禁用；
  - 已保存的标记不删除；
  - 本地标记 Excel 导入/导出仍可在设置页使用；
- 导出主 Excel 不写标记；用户报告在开启时可包含标记；
- 支持 Excel 导入/导出。

### 3.6 匿名抓取与关注增强（FR-008）

默认匿名抓取，不要求 Cookie，不再提供“免登录 / 登录”模式选择。

- 首次启动不再弹模式选择；
- 「抓取」页顶部不再放 `[免登录] [登录]` 切换器；
- 所有核心能力默认可用：
  - 楼层、完整楼中楼、参与者、等级、头衔；
  - 查用户基本资料、最近发言；
  - 隐藏关注候选探测；
  - 红绿灯只看本帖发言；
  - 导出、筛选、对比、报告、备份。

#### 3.6.1 关注增强（可选）

入口：「设置 → 高级 → 关注增强（需要 Cookie）」

- 默认关闭；
- 开启时必须提供包含 `BDUSS` 的 Cookie；
- Cookie 只用于读取对方**没有隐藏**的公开关注列表；
- 不改变抓取、楼中楼、导出等核心能力；
- 关闭后立即回到匿名行为，不需要重启；
- 不根据 Cookie 是否存在自动开启；
- 任何页面都不显示 Cookie/BDUSS 明文。

能力差异：

| 能力 | 默认匿名 | 关注增强开启 |
|---|---|---|
| 抓取 / 完整楼中楼 | ✅ | ✅ |
| 基本资料 / 最近发言 | ✅ | ✅ |
| 公开关注列表 | 🟡 部分 | ✅ 公开部分完整 |
| 隐藏关注完整列表 | ❌ | ❌ |
| 红绿灯：本帖发言 | ✅ | ✅ |
| 红绿灯：关注列表 | ❌ | ✅ |
| 隐藏关注标黄 | ❌ | ✅ |
| 吧务删除内容 | ❌ | ❌（已砍掉） |

#### 3.6.2 红绿灯规则

- 红绿灯开关默认开启，保留「设置 → 通用」开关；
- 默认匿名：
  - 只使用本帖已抓到的发言吧（`user.bars`，含楼层和楼中楼）；
  - 只做本地 `classify`；
  - 不请求资料/关注；
  - 不触发隐藏关注标黄；
  - 没命中 → 白灯。
- 关注增强开启：
  - 数据来源：本帖发言 + 最近发言 + 公开关注 + 精选/等级恢复/候选确认；
  - 命中禁止 → 红灯；
  - 隐藏关注且未命中禁止 → 黄灯 + ⚠；
  - 没有命中 → 白灯。
- 颜色优先级：红 > 黄 > 绿 > 白；
- 查用户页不参与红绿灯；
- 默认匿名批量只跑发言判定，不发资料/关注请求；
- 关注增强批量可查资料/关注；
- 按钮、日志、开关界面见 [ui-spec.md](ui-spec.md) UI-001 / UI-002 / UI-012。

#### 3.6.3 资料查看与红绿灯解耦

- 默认匿名查看单个用户资料时，允许请求公开资料用于展示；
- 但这些结果不得用于红绿灯；
- 批量红绿灯期间不得因为选中行、刷新表格或缓存回填触发资料请求；
- 日志必须区分“一键红绿灯（仅发言）”和“查资料”。

### 3.7 Android（暂缓）

- 当前暂缓实施，先完成桌面版验收；
- 同一套 Python 核心；
- WebView 界面 + 本地 HTTP 服务；
- 暂定范围：匿名抓取、仅发言红绿灯、查用户、导出；
- 暂定不做：批量红绿灯、本地标记 Excel 导入导出、快照。

### 3.8 多帖参与者对比（FR-010）

- 入口：「表格查看」→「参与者对比」子表；
- 列出当前已抓帖子，勾选至少 2 个；
- 只使用已抓数据，不触发网络请求；
- 身份匹配：用户 ID → 用户名 → 昵称；
- 同一帖子内同一用户只算一次；
- 固定四种模式：
  - **交集**：在所有选中帖子都出现；
  - **并集**：在任意选中帖子出现；
  - **仅在 A**：在 A 出现，且不在其他任何选中帖出现；
  - **A − B**：在 A 出现，且不在 B 出现（其余选中帖忽略）。
- A、B 为勾选顺序的前两个帖子，界面显示帖子标题，避免“A 是谁”；
- 结果列：昵称、用户名、用户 ID、各帖计数、合计、类型；
- 支持排序、复制、导出当前对比结果；
- 少于 2 个帖子时提示，不生成空表；
- 对比结果不受参与者筛选影响。

### 3.9 单用户报告导出（FR-011）

- 入口：
  - 「查用户」页导出报告；
  - 「参与者」页选中某人，右键导出此人报告。
- 输出两份文件，同目录、同文件名：
  - `用户报告_昵称_用户ID_时间.xlsx`
  - `用户报告_昵称_用户ID_时间.md`
- Excel 工作表：
  - 基本信息：昵称、用户名、ID、等级、粉丝、关注数、发帖数、关注增强状态、导出时间；
  - 关注贴吧：吧名、等级、是否隐藏恢复；
  - 最近发言：日期、类型、贴吧、标题、内容、链接；
  - 本帖参与：楼层数、楼中楼数、合计、首次出现楼层；
  - 本地标记：仅在启用时写入颜色和命中吧名。
- Markdown 包含同样内容，链接可点击，适合贴到聊天/文档；
- 文件名中的 emoji 用 `[U+XXXX]` 或用户 ID 替代，避免非法字符；
- 未开启关注增强时关注表标注“可能不完整”；
- 报告不包含 Cookie；
- 本地标记关闭时不写标记。

### 3.10 配置备份 / 恢复（FR-012）

- 入口：「设置」→「通用」→「备份配置 / 恢复配置」；
- 备份范围固定为：通用设置、关注增强开关、红绿灯开关、本地标记；
- **不包含 Cookie**；
- 支持两种格式：
  - 单个 JSON（`贴吧统计配置_时间.json`）；
  - ZIP（内含 `config.json` 和 `README.txt`）；
- JSON 顶层包含 `schema_version`、`kind`、`exported_at`、`settings`、`blacklist`；
- 恢复流程：
  1. 选择 `.json` 或 `.zip`；
  2. 预览关注增强状态、本地标记数量、导出时间；
  3. 提示会覆盖当前设置和本地标记；
  4. 自动生成当前配置的临时备份；
  5. 确认后写入；
  6. 提示“重启后完全生效”。
- 非法/损坏/版本不支持的文件：只提示，不覆盖现有配置；
- 恢复不涉及 Cookie、快照、抓取历史。

### 3.11 吧务删除内容（已砍掉，FR-013 撤销）

本功能不再作为产品功能：

- 不要求吧务权限；
- 不保存、不读取、不输入 `STOKEN`；
- 不提供「吧务」标签；
- 不调用 `get_bawu_postlogs` / `get_recovers` / `get_recover_info`；
- 不提供恢复 / 删除 / 屏蔽操作。

删除痕迹的替代研究放到 `backlog.md`，只做“疑似痕迹”，不承诺主动/被动删除分类。

### 3.12 全量楼中楼（FR-014）

目标：默认匿名也能抓完整楼中楼；floor 失败且有关注增强 Cookie 时，才回退网页。

- 抓取深度：
  - 默认「全部」；
  - 可选「每层前 10 / 50 / 100 条」；
  - 选择限条数时，超过部分不再请求。
- 默认流程：
  1. `page` 接口取楼层 + 前 10 条预览；
  2. 对每层请求 `/c/f/pb/floor?cmd=302002`，按 `pn` 翻页；
  3. 按评论 `pid` 去重合并；
  4. 达到 `has_more=false` 或深度上限停止。
- 回退流程（仅当已开启关注增强并带 Cookie）：
  1. floor 失败（网络/超时/5xx/protobuf 错误/异常空结果）时，回退到
     `totalComment` + `/p/comment`；
  2. 回退时记录日志“第 X 层回退网页”；
  3. 两条路径结果按 `pid` 去重。
- 并发：
  - 默认 1（顺序）；
  - 设置中可调 1~3；
  - 并发越高越快，但风控风险越高，界面需提示。
- 失败处理：
  - 单层失败不终止整个帖子；
  - 保留该层前 10 条预览，并记录警告“该层楼中楼不完整”；
  - 重试 1~2 次后仍失败才回退/放弃。
- 保护上限：
  - 每层最多 50 页；
  - 单个帖子最多 2000 次楼中楼请求；
  - 超过上限停止并提示；
  - 支持中途停止。
- 进度：
  - 显示“楼中楼：X/Y 层，已抓 N 条”；
  - 失败/回退逐层记录。
- 证据状态：
  - 匿名 floor 翻页已实测（见 protocol.md）；
  - 关注增强态 floor 回退尚未实测，实现前需补证据；
  - 回退逻辑属于设计，待实现时验证。

### 3.13 隐藏关注候选探测（FR-015）

前提：对方关注列表隐藏（`followed_private` 或 `priv_like == 3`）。

- 入口：
  - 「查用户」页；
  - 「参与者」详情页。
  - 仅在检测到关注隐藏时显示「探测候选关注」按钮。
- 候选吧来源（只取这些，不允许自由输入或全站遍历）：
  - 本帖发言吧；
  - 最近发言吧；
  - 本地标记中的吧。
- 流程：
  1. 汇总候选吧并去重；
  2. 排除已在公开关注/精选关注里的吧；
  3. 最多探测 30 个候选；
  4. 逐个调用 `get_user_forum_info(吧名, uid)`；
  5. `is_follow=True` 的加入关注表。
- 展示：
  - 关注表增加「来源」列：公开 / 精选 / 等级恢复 / 候选确认；
  - 候选确认的行标注「推断」，并提示“只验证了候选吧，仍可能不完整”；
  - 不能显示成“完整关注列表”。
- 红绿灯：
  - 候选确认的 `is_follow=True` 可参与命中判定；
  - 但“关注列表隐藏”风险规则仍保留：未命中禁止时仍标黄 + ⚠。
- 限制：
  - 手动触发，不自动跑；
  - 最多 30 个候选，单次探测；
  - 沿用请求间隔，可中途停止；
  - 结果只在当前会话缓存，不写入配置/备份；
  - 用户报告导出时可按当前关注表包含，并保留「来源」列；
  - 不做“遍历所有贴吧”。
- 错误：
  - 吧不存在/无权限：跳过该候选，继续；
  - 连续失败/被限流：停止并提示；
  - 用户无公开资料：提示无法探测。
- 证据：
  - 匿名 `get_user_forum_info` 已实测可返回 `is_follow`；
  - 隐藏用户 `priv_like=3` 实测；
  - 关注增强态行为未单独验证。

### 3.14 凭据与能力边界

凭据分级、能力矩阵和“Cookie 也不能做到”的完整规则，统一放在
[credentials.md](credentials.md)，本文件不重复维护。

功能验收只保留三条：

- 无 Cookie 能完成核心抓取、完整楼中楼、统计和导出；
- 只有开启关注增强并填入 BDUSS，才读取公开关注、红绿灯关注判定；
- 隐藏关注仍然无法完整枚举；
- 不提供吧务删除内容，不保存 STOKEN。

## 4. 非功能需求

- Windows 版为免安装目录，双击 exe 即可；
- 不要求目标机器安装 Python；
- 请求间隔可配置，默认 ≥0.3 秒，避免触发验证；
- Cookie 本地保存：Windows 使用 DPAPI，Android 存 App 私有目录；
- 日志不得输出 Cookie/BDUSS；
- 抓取失败要给出可理解的错误（验证、删帖、网络）；
- 支持离线自测（fixtures），不依赖网络。

## 5. 明确不做

- 不提供贴吧发帖/回复/签到等写操作；
- 不自动登录、不绕过验证码；
- 不做吧务后台、删除内容恢复、STOKEN 相关功能；
- 不承诺完整枚举隐藏关注列表；
- 不提供官方 API 或数据合作；
- 不做多用户 SaaS、不做公网服务。
