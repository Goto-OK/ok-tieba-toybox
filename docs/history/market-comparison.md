# 贴吧相关项目横向对比

对比基准：本项目当前规范（默认匿名、可选关注增强、完整楼中楼、统计/导出、不写操作）。  
目的：找差距、定优先级，不照搬别人的功能。

## 3. 本项目的优点

1. **匿名优先**：核心抓取、完整楼中楼、统计、导出都不需要 Cookie，市面多数工具要么登录、要么只做爬虫。
2. **终端用户视角**：Excel、参与者筛选、多帖对比、单用户报告、配置备份，比接口库/爬虫更接近“拿来就用”。
3. **安全边界清楚**：不做发帖/回复/封禁/删帖，不保存 STOKEN，关注增强只读公开关注。
4. **隐藏关注候选探测**：这是很少见的边缘能力，且有明确“不完整”标注。
5. **证据与规范**：接口结论附实测，功能有 FR/UI 编号，状态区分规范/源码/测试/成品。
6. **Android 版**：多数同类项目只有 Python/命令行。

## 4. 本项目的缺点

1. **没有持久化历史**：结果在内存，重抓/多帖/断点能力弱；规范已要求增量，但代码未实现。
2. **同步 HTTP**：并发和吞吐有限，缺少 async/连接池/自适应限流。
3. **协议覆盖窄**：只覆盖本项目需要的接口，维护靠手工；aiotieba 覆盖更广。
4. **没有数据平台能力**：没有 PostgreSQL/Redis/监控/定时任务/分布式。
5. **没有媒体归档**：只存文本和 Excel，图片/视频/语音不保存。
6. **没有 Web 版**：Tk 界面和旧 Android，跨平台/远程使用弱。
7. **UI 工程化不足**：`tieba_gui.py` 单文件近 3600 行，布局/日志/按钮问题需要专项修。
8. **没有插件/API**：外部无法复用采集结果，自动化能力弱。
9. **删除痕迹**：只有研究计划，没有可靠实现。
10. **社区与文档影响力**：内部规范完整，但没有公开教程、示例库、Issue 生态。

## 5. 值得借鉴

### 5.1 aiotieba：协议层不要重复造轮子

- 类型化模型、protobuf 请求构造、签名、分页、WebSocket；
- 数十个接口的覆盖和版本跟进；
- CI + 教程 + 示例。

借鉴方式：

- 以 aiotieba 的接口定义/字段作为协议对照；
- 保留本项目轻量实现，但补契约测试；
- 不直接把整个库塞进 GUI，按需封装。

### 5.2 TiebaScraper：数据层和运行模式

- 实时监控 / 历史回灌 / 混合模式；
- PostgreSQL + Redis + Prometheus + Docker；
- 限速、429 重试、动态增删贴吧。

借鉴方式：

- 先做 SQLite 本地历史 + 断点续抓，不直接上 PostgreSQL；
- 任务配置化，支持“一次抓取”和“定期更新”；
- 指标先做日志统计，不急着上 Prometheus。

### 5.3 TiebaSpider：工程化爬虫

- 代理池、断点续爬、分布式、配置化；
- 数据落 MySQL。

借鉴方式：

- 断点续抓、失败重试、请求预算；
- 代理池暂不做，避免复杂度和风控争议；
- 代理接口保持可插拔，但默认关闭。

### 5.4 TiebaArchiver / TiebaReader：归档与离线阅读

- 保存原帖、图片、视频、语音；
- 配套阅读器。

借鉴方式：

- 增加“导出归档包”而不是只导出 Excel；
- 图片/媒体可选下载，默认关闭；
- 阅读器不做，优先复用系统文件/浏览器。

### 5.5 TiebaPostBackupTool：轻量备份思路

- 浏览器脚本、手动触发、自动滚动；
- 明确说明动态加载和限流限制。

借鉴方式：

- 保持“手动触发、可停止、失败保留已抓内容”；
- 不承诺一次备份完整。

### 5.6 Tieba-Manager：只借鉴工作流，不借鉴写操作

- 吧务列表、筛选、批量操作、权限提示；
- 删帖/封禁/黑名单。

借鉴方式：

- 只借鉴列表/筛选/确认流程；
- 不引入删帖、封禁、黑名单写操作；
- 不保存 STOKEN。

## 6. 优先级建议

### P0：先把规范落地

- 默认匿名 + 关注增强；
- 红绿灯默认开启、免登录只按发言；
- 按钮/日志/默认窗口；
- Emoji 统一显示与代码输入；
- 多帖切换 + 增量抓取。

没有这些，横向对比没有意义。

### P1：数据层

- SQLite 保存帖子/楼层/楼中楼/抓取状态；
- 断点续抓、增量更新、失败重试；
- 多帖结果持久化，重启不丢；
- 导出从数据库生成。

### P1：协议与测试

- 用 aiotieba 字段做契约对照；
- 固定 fixtures：楼层、楼中楼、用户资料、关注、错误码；
- 关键接口失败降级测试。

### P2：可选增强

- 定时更新/监控（本地，不开公网）；
- 归档包（文本 + 可选媒体）；
- Web UI 或更好的 Android；
- 插件/API 输出 JSONL。

### P3：研究项

- 无吧务权限的删除痕迹；
- 只做“疑似”，不做主动/被动分类；
- 先验证页面占位、声明/实际差、楼层缺口。

## 7. 不建议学

- 删帖、封禁、黑名单写入；
- 保存 STOKEN；
- 绕过验证码/风控；
- 大规模代理池/分布式抓取；
- 未经同意抓取私密内容；
- 把“疑似删除”宣传成“已删除查询”。

## 8. 结论

本项目的差异化不是“接口最多”或“爬得最快”，而是：

```text
默认匿名 + 完整楼中楼 + 面向人的统计/报告 + 明确的只读边界
```

需要补的是工程底座（历史、断点、并发、测试），不是继续堆功能。
